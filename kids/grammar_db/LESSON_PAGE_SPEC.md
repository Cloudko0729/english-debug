# 節點教學頁建置規範（Lesson Page Spec）

> 適用範圍：`kids/grammar_db/` 48 個節點的孩子端教學頁。
> 狀態：家長 2026-07-26 核可，**建置任何節點頁都必須遵守**。
> 參考實作：`kids/grammar_db/preview/F2.3-present-continuous.html`

資料庫每個節點的欄位很完整（4 例句、2 組對照、2 組中文遷移 bug、3 題診斷、口說寫作任務、對話…），
但**不可以把資料庫欄位一次全部攤開在頁面上**。資料完整是給教學引擎用的，孩子端要「漸進式呈現」。

---

## 1. 固定五步驟，其餘收起來

每個節點頁一律照這個順序，**只顯示以下內容**：

| 步驟 | 內容 | 取自資料庫 |
|---|---|---|
| ① 生活情境 | 一段情境開場，讓孩子知道「什麼時候會用到」 | `dialogue.turns`（4 輪對話） |
| ② 今天的任務 | **一句話**講完今天要學會什麼 | 改寫自 `communicativeGoalZh` |
| ③ 核心例句 | **只放 2 句**，不是一次 4 句 | `naturalExamples[0..1]` |
| ④ 最小對照 | **只放 1 組** | `contrastPairs[0]` |
| ⑤ 診斷＋輸出 | 3 題診斷 + 1 個輸出任務 | `diagnostics`、`productionTasks` |

**其餘內容一律收進「👀 再看一點」或「🤔 為什麼？」的摺疊區**：
剩下 2 個例句、第 2 組對照、`form` 形式字串、中文遷移 bug、完整 SVG。

**單節課首次學習控制在 8–12 分鐘。**

### 標題文案規則

`communicativeGoalZh` 和 `form` 是資料欄位，**不可以直接當孩子看到的標題**。

- ❌ 孩子端標題寫：`Subject + be + V-ing`
- ✅ 孩子端標題寫：「今天你要學會：告訴別人**現在正在做什麼**」
- `form` 的公式字串收進「🤔 為什麼？」抽屜裡再顯示

---

## 2. E0–E3 不對孩子顯示代碼

孩子端一律翻成看得懂的說法，**家長端／資料層仍保留原始 E0–E3 代碼**（排課與追蹤要用）。

| 資料層 | 孩子端顯示 |
|---|---|
| E0 | 🔴 意思跑掉了 |
| E1 | 🟠 句型少了零件 |
| E2 | 🟡 聽得懂但卡卡的 |
| E3 | 🔵 這樣說也可以 |

---

## 3. 圖像：情境圖優先，逐月累積

- **不要**為了美觀增加大量裝飾插圖。
- 要增加的是**能直接表達文法差異的情境圖**（例如雙格對比圖）。
- 每個等級固定一組**會反覆出現的角色與場景**，讓孩子有連續感：

| 等級 | 固定情境 |
|---|---|
| F0 | 家庭與小島物品 |
| F1 | 學校、寵物、問答 |
| F2 | 每日作息與正在發生的事 |
| F3 | 旅行與昨天的事件 |
| F4 | 城市規劃、比較與規則 |
| F5 | 經驗、選擇與條件 |
| F6 | 科學實驗、流程與報告 |
| F7 | 簡報、文章修改與自然表達 |

- **第一版不用一次畫滿 48 張**。每月只製作該月實際選到的 3–5 個節點的情境圖，逐月累積。

---

## 4. 手機版 SVG 呈現

現有 19 張 SVG 是 760×440 固定尺寸，手機上靠橫向捲動（`diagram_embed.css`）。
圖不會壞，但**左右拖動會增加孩子的理解負擔**。

規則：

- 手機版**不要**把整張 SVG 硬縮小（字會太小）。
- 手機版預設只呈現「**目前相關的那一個分支**」，改用**直式卡片**排版。
- 完整 SVG 收進「📊 看整張規則圖」的選項裡，需要時才展開（此時才用橫向捲動）。

---

## 5. 語音一律用預錄音檔，禁止機械音

全站規則：英文語音一律使用預先生成的 Kokoro MP3，`browserSpeechFallback` 固定為 `false`。

⚠️ **已知待修**：舊的 `kids/lessons/*.html` 教學頁，其**文法規則例句**沒有預錄音檔，
目前會 fallback 成瀏覽器 `speechSynthesis`（機械音），與全站規則不一致。
新節點頁不得沿用這個做法；舊頁面待補音檔修正。

NotebookLM 產生的 Podcast／影片屬於額外教學素材，與逐句 Kokoro 語音並存，不互相取代。

## 6. 媒體檔壓縮（NotebookLM 產出）

NotebookLM 原始輸出過大，**入庫前必須壓縮**（實測單節點 32MB → 4.8MB，約省 85%）：

```bash
# 音檔：講話內容不需要 256kbps 立體聲
ffmpeg -i in.m4a  -c:a aac -b:a 48k -ac 1 -movflags +faststart out-min.m4a

# 影片：480p 對教學文字仍清晰
ffmpeg -i in.mp4 -c:v libx264 -crf 30 -preset slow -vf "scale=854:480" \
       -c:a aac -b:a 48k -ac 1 -movflags +faststart out-min.mp4
```

容量限制背景：

- GitHub Pages 網站上限 **1GB**，**付費升級方案不會提高這個限制**。
- **不可以用 Git LFS**：Pages 不解析 LFS，會把指標文字檔直接吐給瀏覽器，媒體會全部壞掉。
- 目前網站約 421MB；48 節點壓縮後約 +230MB，落在 650MB 左右，安全。未壓縮則會爆表。

NotebookLM 匯出的「mp3」實際是 AAC-in-MP4，**副檔名要存成 `.m4a`**，
存成 `.mp3` 在部分瀏覽器（iOS Safari）可能播不出來。

## 7. 播放器顯示邏輯

媒體檔跟頁面一起發佈，**有檔案是常態**，所以：

- 播放器**預設顯示**，只有音檔與影片**都真的 error** 才隱藏並退回逐句語音。
- **不要**把顯示判斷掛在 `loadedmetadata` 上：若元素是 `preload="none"`，該事件永遠不會觸發，
  會誤判成「沒有檔案」而永遠顯示 fallback（此 bug 已於 2026-07-26 修正，勿重蹈）。
- `preload` 用 `metadata`，播放器才會顯示長度。
